## v2:6c721f9cec5e64e400e51aca1e3fb91ac48415a1f1b598e35ad55d756e333f42 (W8) — tests 237

- CAVEAT: Order of steps: the task text says 'protected regions ... then formatters', but design section 13 (binding) says format first, then merge regions. I followed the design: the formatter sees the generated text, and the hand-written region bodies go back in unformatted. As a consequence, a formatter that rewrites the 'maquettiste:keep id=...' marker lines makes the disk regions look lost (MQ6010); a test shows this.
- CAVEAT: Constraint and index keys are derived, not taken from the model. The design (section 14) says snapshots are 'keyed by section 7.3 keys', but section 7.3 only defines keys for tables, columns and sequences, and the resolved constraint types (RPrimaryKey, RUnique, RForeignKey, RCheck, RIndex) carry no key or id. The derived keys are: 'pk'; 'uq:<column keys>'; 'fk:<column keys>'; 'ix:<column keys>' (with ' desc' for descending); 'ck:<16 hex of SHA-256 of the expression>'; repeats get '#2', '#3', ... in name order. So renaming a constraint or index is reported as Renamed, but changing its columns (or a check's expression) is reported as a drop plus an add. RPrimaryKey also has no Clustered, so snapshots never record it. See signatureChangeRequests.
- CAVEAT: TableChange has no list of property changes. A change to a table's schema or comment therefore shows as Altered with empty sub-lists and the old value is lost. This contradicts design section 14's promise that comment changes surface as Altered with PropertyChanges; that promise holds for columns, views and sequences, but not for tables. See signatureChangeRequests.
- CAVEAT: SchemaDiffResult holds RTable and RColumn objects, which reference each other (RColumn.Table leads back to RTable.Columns). Serializing a SchemaDiffResult with System.Text.Json Web defaults will therefore fail on the cycle, which conflicts with host-contracts requirement 5. This comes from the scaffold's types, not from W8 code.
- CAVEAT: Region conflicts are not reported as a Conflict file change. A lost or malformed region on disk fails the unit with an MQ6010 error and returns no files, so the writer keeps the old file. W7 does not produce a FileChangeKind.Conflict for it; the CLI (W9) must map MQ6010 to exit code 3.
- CAVEAT: W7 must hash a regions file on disk with the internal helper ProtectedRegions.SkeletonHash(normalized text) and compare that with the r: entry in the manifest. Otherwise edits inside a region will be reported as hand edits.
- CAVEAT: 'Run over changed files only' is met because only rendered (non-skipped) units reach stage 7. Nothing further filters out rendered files whose content is unchanged.
- CAVEAT: A formatter named by a unit is applied to every file that unit produces, including file blocks with other extensions. Extension matching is case-sensitive ordinal: '.sql' does not match 'X.SQL'.
- CAVEAT: Formatter version pinning is also checked lazily inside PostProcessor when PostProcessContext.FormatterVersionsVerified is false. A mismatch then fails every unit that would use that formatter, one diagnostic per unit, instead of failing the whole run. The orchestrator (W6) is still expected to call VerifyVersionsAsync up front and fail the run.
- CAVEAT: The snapshot file name comes from a local kebab-case helper (SnapshotStore.Kebab, following the section 9 word rule), because W3's Casing.Words is still a stub. Switch to Casing.Words once W3 merges, and check that the two agree.
- CAVEAT: Snapshot files are named after the database, as ISnapshotStore.LoadAsync(databaseName) requires. If a database is renamed, its old snapshot is no longer found and the next diff reports every table as Added.
- CAVEAT: SnapshotStore.LoadAsync throws InvalidDataException for a corrupt snapshot, and SaveAsync throws UnauthorizedAccessException when the path policy refuses. The orchestrator (W6) has to turn these into diagnostics.
- CAVEAT: Changes in column order are not reported, because no snapshot property records a column's position.
- CAVEAT: The main formatter tests need Python on PATH; they call Assert.Skip if it is missing. In this run python3 was present and nothing was skipped. CI runs on ubuntu and macos, where GitHub runners include python3.
- CAVEAT: Spec versus design: SPEC section 12 names the template variable schemaDiff, while design section 8 uses schema_diff. Wiring that variable into the template context belongs to W5/W6; W8 only produces the SchemaDiffResult values.
- SIGNATURE REQUEST: Resolution/ResolvedPhysical.cs: add `public string Key { get; internal set; }` to RPrimaryKey, RUnique, RForeignKey, RCheck and RIndex. The value would be the model's constraint or index id (UniqueConstraint.Id, ForeignKey.Id, CheckConstraint.Id, TableIndex.Id), or a synthesized key defined in design section 7.3 (for example '<tableKey>.pk'). The snapshot and differ would then use real stable keys instead of keys derived from content.
- SIGNATURE REQUEST: Resolution/ResolvedPhysical.cs: add `public bool? Clustered { get; internal set; }` to RPrimaryKey (from PrimaryKey.Clustered), so SnapshotConstraint.Clustered can be captured.
- SIGNATURE REQUEST: SchemaDiff/SchemaDiffTypes.cs: add `IReadOnlyList<PropertyChange> Changes` to TableChange (for example right after NewName), holding table-level changes such as 'schema' and 'comment', as design section 14 promises for comment changes.

- CAVEAT: Script errors are thrown as a new INTERNAL type, ScriptErrorException (Scripting/SandboxRuntime.cs), carrying a Diagnostic with rule MQ6016 or MQ5002. Section 10 names only ScriptLimitException. W2, W5 and W6 must catch ScriptErrorException and ScriptLimitException and read .Diagnostic; OperationCanceledException means cancellation.
- CAVEAT: CreatePool throws when a script has a syntax error, throws while loading, or hits a limit while loading (ScriptErrorException or ScriptLimitException). The pool has no channel for load diagnostics, so callers must catch at CreatePool.
- CAVEAT: Rule scripts versus pack scripts (MQ5002/MQ5003 versus MQ6016/MQ6007) are told apart by the script path containing 'extensions/rules/'.
- CAVEAT: RunRule returns MQ5002 diagnostics for a rule that throws or returns bad values, placed after any reports the rule made before failing. It throws ScriptLimitException (MQ5003) for limit breaches, and ScriptErrorException (MQ5002) for an unknown rule id. RunRule skips elements whose kind is not in the rule's kinds, so W2 need not filter. Report diagnostics have Line and Column null; W2 should fill them from the pointer.
- CAVEAT: Choices the design leaves open: helpers are called as fn(...args); selectors as fn(model), returning model objects or id strings; filters and transforms as fn(element, model); rules as check(element, model, report). Pack parameters are read through the accessor maquettiste.params. Transforms must return a plain object or null.
- CAVEAT: Values out of scripts: plain objects come back as an internal ScriptObjectMap (an IReadOnlyDictionary that keeps JS property order); arrays as IReadOnlyList<object?>; integral numbers within ±2^53-1 as long; proxies as the original CLR object. Values into scripts: CLR maps become frozen objects with keys in ordinal order. Dates, promises (so any async helper), functions, symbols and BigInt cannot leave a script and are script errors.
- CAVEAT: Lists reach scripts as frozen array-likes with Array.prototype as their prototype. map, filter, for-of and spread work, but Array.isArray(list) is false and concat will not spread them.
- CAVEAT: Deep-freezing every intrinsic brings the strict-mode 'override mistake': assigning a property such as toString directly on an ordinary object (obj.toString = f) throws a TypeError. Object literals, classes and defineProperty still work. This follows from the design's 'deep-freeze globalThis'.
- CAVEAT: Additions beyond section 10, made for host safety and determinism: StackOverflowGuard (without it, JSON.stringify of deeply nested data crashed the test process); MaxArraySize = ScriptMemoryBytes/16; guarded String.prototype.repeat/padStart/padEnd; RegexTimeout = min(ScriptTimeoutMs, 500 ms); a custom constraint that also watches the per-call token while a script runs; typed arrays, ArrayBuffer, SharedArrayBuffer, DataView, Atomics, WeakRef, FinalizationRegistry and ShadowRealm removed. Temporal and Intl remain; they use the fixed clock, UTC and invariant culture.
- CAVEAT: Remaining risk: Jint's memory limit counts bytes allocated on the calling thread and checks only between statements. A single built-in call other than the guarded ones (for example join with a huge separator) can overshoot before the check. A regex already running when cancellation arrives can keep the thread busy for up to 500 ms.
- CAVEAT: The one-second cancellation tests time from Cancel() to the exception reaching the awaiting test, including task scheduling. They take about 300 ms locally but could be tight on a heavily loaded CI machine.
- CAVEAT: Every limit applies per top-level call: each helper call, selector, filter, transform or rule check starts with fresh limits, as SPEC S19 describes. A unit that calls a helper many times therefore gets the limit budget once per call, not once per unit.
- CAVEAT: Jint 4.16.4 API differences from the design text: Culture, TimeZone and TimeSystem are Options properties (there are no Culture()/LocalTimeZone() extension methods); Engine.PrepareScript is static. The behaviour matches the design.
- SIGNATURE REQUEST: Optional, design text only (no code change needed): add to engine-design.md section 10 that script errors are thrown as ScriptErrorException(Diagnostic) with MQ6016 (pack scripts) or MQ5002 (rule scripts), alongside ScriptLimitException, and that IScriptSandboxFactory.CreatePool throws these for load failures. If hosts outside the engine assembly ever need to catch it, promote it to `public sealed class ScriptErrorException : Exception { public ScriptErrorException(Diagnostic diagnostic, Exception? inner = null); public Diagnostic Diagnostic { get; } }` in Scripting/ScriptingContracts.cs; today it is internal in Scripting/SandboxRuntime.cs.

## WB (one-shot CLI) — tests 1,454 after the review fixes (engine 1,294, CLI 104, packs 27 plus 2 skipped without database containers, bench 27)

- DECISION (design correctness rules for caches, recorded as D45 and in `src/Maquettiste.Engine/Generation/README.md`): no
  persisted resolved model. The design's caches are content-addressed inputs (§5 index cache) or run outputs checked against the
  disk (§11 unit states), so a stale or damaged cache costs a re-read, never a wrong model. A serialized resolved model would be a
  derived graph of about 330,000 objects whose every member needs a serializer kept in step with the resolver (a missed member
  silently changes rendered bytes), and decoding it in a fresh process costs about what resolving does. Instead a one-shot host
  keeps a last-run record that answers a run whose inputs did not change (by stat) with the full run's result, skipping load and
  validation too. It is written only when the next full run would provably be a no-op (every planned unit's state current, no
  pending schema diff, no MQ6004/5/9/10/15, no journal left).
- CAVEAT: The record trusts stats for model files and sidecars (as the index cache does), outputs (as the skip check does) and the
  engine-only unit-state and built-root manifest files; templates, committed manifests and schema snapshots are compared by content
  (review fix). A tool that rewrites a model file with the same length within one timestamp tick is not seen until something else
  changes (`--force` or deleting `<cache-dir>/last-run.v1.bin` recovers), as with the index cache.
- CAVEAT (review fixes): the record's key and header name the engine build (`RunRecord.CurrentBuild`: module version ids of the
  engine and entry assemblies, runtime version, .deps.json bytes), not only `EngineVersion.Value`; the trailer is checked before any
